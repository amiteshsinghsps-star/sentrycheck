# Evidence and architecture corrections

The implementation preserves the PRD's hybrid-analysis goal while correcting claims that would otherwise produce unsafe or misleading output.

1. **gVisor syscall tables are not workload verdicts.** The [official compatibility guide](https://gvisor.dev/docs/user_guide/compatibility/) explicitly explains runtime probing and fallback. Static capability candidates therefore stay separate from findings. Native-only observations are risks, not reproduced incompatibilities.
2. **Use the selected release, not a live website as historical evidence.** The bundled snapshot is generated from [commit 26f3455a4cb9a377354c33aeac049080a077c79c](https://github.com/google/gvisor/tree/26f3455a4cb9a377354c33aeac049080a077c79c), resolved from `release-20260921.0`. The two architecture tables contain release-specific entries; hardcoded aggregate support counts are not used as a compatibility score.
3. **BPF is more nuanced than a blanket unimplemented syscall.** That release's table documents support for loading/querying/attaching CGROUP_DEVICE programs while stating that loaded programs have no effect. This can be a silent semantic issue. A BPF symbol does not establish an unsupported program type or a crash.
4. **In-sandbox cgroup limits differ from host sandbox limits.** The guide says accounting works and limits between processes inside the same sandbox are not enforced. Host cgroups can still limit the entire sandbox. Reports preserve that distinction.
5. **A missing RuntimeClass handler is normally an error.** [Kubernetes RuntimeClass documentation](https://kubernetes.io/docs/concepts/containers/runtime-class/) states that an unavailable/unrunnable handler causes Pod failure with an event. SENTRYCHECK detects missing handlers and observed runtime mismatches without asserting that Kubernetes specifies silent fallback.
6. **CEL mutation is not external verification or rejection.** [ValidatingAdmissionPolicy](https://kubernetes.io/docs/reference/access-authn-authz/validating-admission-policy/) supplies Warn/Deny/Audit. A controller supplies signed report and node-health parameters. Optional [MutatingAdmissionPolicy](https://kubernetes.io/docs/reference/access-authn-authz/mutating-admission-policy/) adds metadata only. Neither policy can fetch registry reports or establish real-time node identity.
7. **Dynamic analysis is an execution surface.** Running untrusted images under runc and managing CRI canaries is not read-only analysis. The environment prerequisites and trust boundaries are documented in SECURITY.md.
8. **Unnamed sources cannot seed verified rules.** No exact URL was supplied for the July 2026 post-mortem or live GitHub issue. Their claimed cases are not marked verified, and their quotations are not reproduced as sourced facts. Generic filesystem/timing/mismatch observation categories remain useful without asserting those anecdotes.
9. **PostgreSQL/io_uring needs an explicit build and version.** The corpus uses a documented custom PostgreSQL 18 build with `--with-liburing`, not a claim that stock PostgreSQL 16 provides the described backend. An actual native success and sandbox failure must establish the label for the selected image and runtime.
10. **Research novelty and release readiness need evaluation.** No exhaustive competitive-landscape claim, publication result, arXiv submission, trademark clearance, or live-demo success is fabricated. A reproducible evaluation runner and release checklist are included.

Source retrieval URLs, times, and hashes are recorded in `docs/evidence/sources.json`. A retrieval proves what was fetched at that time; release applicability comes from the immutable source revision, not the retrieval date.
