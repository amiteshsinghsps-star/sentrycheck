# BM-01: Compatibility Accuracy (SentryBench-Core)

## Objective
Measure how well SENTRYCHECK's predictions agree with independently established sandbox outcomes across the registered corpus.

## Ground Truth Procedure
1. Workloads are executed natively (under `runc`) and under the target sandbox runtime (`runsc` / gVisor) with debug logging enabled.
2. Exit codes, stdout/stderr streams, and guest strace logs are recorded.
3. Outcome classes are assigned:
   - `hard-failure`: Process terminated unexpectedly or returned fatal error code under sandbox.
   - `silent-degradation`: Process exited 0 but output diverged from native reference.
   - `tolerated`: Workload gracefully handled denied syscall / capability stub.
   - `compatible`: Identical exit code and matching behavior between native and sandbox.
4. Two raters assign ground-truth labels independently; adjudicator resolves discrepancies.

## Prediction Mapping (BT-01)
- `hard-failure`: any finding with severity `hard-failure` and dynamic tier.
- `silent-degradation`: any finding with severity `silent-degradation`.
- `tolerated`: recorded fallback finding without fatal findings.
- `compatible`: complete scan status with dynamic diff tier and no high-severity findings.
- `indeterminate`: incomplete scan, stale KB, or static-only analysis.

## Metrics
- Precision, recall, and F1 per class with Wilson 95% confidence intervals.
- McNemar test with Holm step-down correction against B0 (naive) and B5 (just-run) baselines.
