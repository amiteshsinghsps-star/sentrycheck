# Known limitations

This document is part of the product contract. No result is a formal compatibility or isolation proof.

* **Coverage is profile-bounded.** Default ENTRYPOINT/CMD execution is a smoke test and stays incomplete. Representative profiles are explicit user assertions about input coverage, not a coverage proof. Undeclared persistent state, external services, mounted executables, and dynamically generated code are not exhaustively explored.
* **Static extraction is incomplete.** x86 uses instruction decoding and conservative constants within straight-line blocks. ARM64 resolves adjacent MOVZ/MOVK into x8/w8 only. General register arithmetic, interprocedural dispatch, indirect calls, self-modifying code, packed binaries, big-endian ELF, extended ELF numbering, and unsupported architectures remain unknown. Without section metadata, entry-point alignment can leave earlier code unanalyzed. A resolved syscall number does not establish arguments or reachability.
* **Metadata is weaker than behavior.** GLIBC symbol versions are requirements, not the installed libc version. Library links and strings are probable markers. No release-specific libc/libuv fallback guarantee has been seeded without a verified source; the current fallback-rule list is deliberately empty.
* **Image limits are explicit.** Maximum individual file 256 MiB, live in-memory rootfs 1 GiB, cumulative expanded layer data 4 GiB, 100,000 paths, 512 layers. zstd layers, non-UTF-8 paths, special files, forward hardlink chains, and paths requiring traversal through archive symlinks are unsupported or rejected. Device entries are omitted with warnings. Supported OCI hardlinks retain shared file content, target permissions, and shared inodes when materialized. Directory modes are preserved, and cleanup handles restricted directories without following symlinks. Ownership, xattrs, ACLs, file capabilities, and special permission bits are not fully reconstructed; applications depending on them can behave differently.
* **OCI configuration is validated before execution.** Command, environment, user, and working-directory declarations must have supported types and values. Invalid empty values, NUL bytes, malformed environment entries, and relative working directories are rejected. Only explicitly supported manifest/config/layer media types are accepted; gzip decoding includes concatenated streams. These checks do not establish that an otherwise valid image will execute correctly.
* **Incremental work is at the ELF level.** Content-addressed ELF analysis uses `elf-v3` cache entries. Layer digest verification and overlay construction still run for every scan; this is not a zero-cost layer cache. Mutable registry tags are resolved on every scan. Admission requires the selected **platform manifest digest**, not an unrelated multi-architecture index digest. Declared CPU variants are limited to amd64/v1 and arm64/v8; absent variants are accepted. Unsupported declared variants and CPU features are rejected. Matching these declarations does not prove CPU portability or detect every instruction-set requirement inside a binary.
* **The runner is isolated, not transparent.** It uses a new writable rootfs for every repetition, fresh namespaces, no external networking, dropped capabilities, resource limits, bounded logs, and a trusted injected tracer. Host mounts, ports, privileged eBPF loading, device workloads, and arbitrary network scenarios are not enabled. Rootless mode currently supports USER 0; other image users need a dedicated rootful runner. Namespace/cgroup/pid permissions and sufficient temporary disk space are prerequisites. Runtime deletion must succeed before reading guest trace files or cleaning the rootfs. A deletion error leaves the scan incomplete and preserves the bundle for inspection; the tool does not claim that a failed cleanup stopped the workload.
* **Trace collection is empirical.** Native tracing occurs inside runc; runsc emits its own guest syscall trace. The v0.3 parser validates source framing and balanced records, pairs entries/completions by task ID, and separates recognized `diagnostic_lines` from `discarded_guest_records`. Empty, truncated, malformed, discarded, or unfinished guest evidence prevents a complete scan. Ambiguous text is not silently promoted to a syscall event. A nonempty accepted trace still does not prove that every syscall was captured. The two tracers have different overhead and may alter behavior. An abnormal baseline prevents a sandbox-specific incompatibility conclusion. See [docs/AUDIT-V03.md](docs/AUDIT-V03.md) for the reproduced parser failures behind these checks.
* **Native trace files are writable from the guest.** A malicious workload can alter its native trace or output inside the injected tracer directory. Hashing, local provenance labels, and later signing do not establish adversarially trustworthy execution evidence. Use trusted CI producers and an appropriate trust model; this release is not a tamper-proof attestation system.
* **Diffs do not establish root cause.** The scanner emits one observed workload F1 when native execution succeeds and sandbox execution fails. Correlated syscall/filesystem errors remain `compatibility-risk` findings, since tolerated probes are not proven causes. Deterministic stdout/stderr comparisons depend on profile assertions. Profiles can print measurements of filesystem/resource behavior; the scanner does not independently infer all cgroup semantics. Timing findings include startup and tracing overhead, use at least three repetitions, and do not prove a netstack or gofer regression.
* **KB coverage is exact and time-limited.** The bundled release is 20260921.0, amd64/arm64. No rule is extrapolated to an unverified future version. Snapshots older than the configured age produce incomplete scans. An update selects one verified release snapshot; it does not merge unlimited historical releases. Generation requires the reviewed constructor-source hash, known table layouts, and the reviewed cgroup caveat; upstream changes may require manual review before an update succeeds. The 40 `CapError` stubs are unimplemented even with the named capability: they return EPERM without it and ENOSYS with it. A fully supported table row still does not establish whole-workload compatibility.
* **Kata is experimental.** Native-only analysis and externally supplied Kata guest traces are supported. The portable runner does not launch Kata VMs, and there is no verified Kata release support matrix. Actual Kata execution needs a configured hypervisor and hardware virtualization, commonly KVM, with backend-specific alternatives such as mshv. A gVisor systrap prerequisite check does not establish Kata readiness.
* **Imported traces are not execution attestations.** Hashes bind files, image digest, runtime version, and profile, but cannot authenticate how traces were collected. Imported evidence remains visibly incomplete and the CI signing tool rejects it.
* **Report tools have distinct scopes.** `doctor` checks prerequisites without launching a workload. `report validate` recomputes syscall/errno summary maps from events and checks report consistency; optional artifact checks verify hashes and trace interpretation. A valid report may still be incomplete, and validation is not authentication. `report diff` requires complete reports with matching analyzer/KB/target/profile/evidence, but does not fingerprint host configuration or prove that an absent finding is fixed. Reports from different analyzer versions are not directly comparable baselines, and earlier traces may require revalidation or a new scan after parser changes. See [docs/CI-TOOLS.md](docs/CI-TOOLS.md).
* **SARIF output is not an automatic GitHub integration.** Generic SARIF results without repository locations need not appear as GitHub code scanning alerts. `--source-file`/`--source-line` add a user-supplied context, not an inferred ELF source location. The exporter uses its own fingerprint; GitHub's documented fingerprint support differs, so upload display and deduplication need consumer-specific verification.
* **The offline viewer presents existing evidence.** HTML rendering does not rerun workloads, check artifact files, verify signatures, or make an incomplete scan complete. Browser imports are structurally checked and do not inherit CLI validation. SARIF lacks full static-site and run-summary data; missing evidence stays unavailable. Trace charts show aggregate counts per observation, not timestamps for individual diagnostics. Large reports still require browser memory to parse even though displayed collections are paginated. See [docs/REPORT-VIEWER.md](docs/REPORT-VIEWER.md).
* **Node checks are point-in-time.** A CRI canary checks its requested ID, `SANDBOX_READY` state, and reported runtime type. The probe separately checks the configured binary's version; this does not prove which executable the CRI shim launched. It is not cryptographic hardware attestation or proof about all already-running Pods. Drift can occur after a check; absent or inconsistent canary identity/status/runtimeType means unverified. Unresolved CRI/CNI or cleanup errors prevent verified health; bounded retries retain transient-error diagnostics. Healthy-node selection accounts for RuntimeClass selectors but does not prove that Pod-specific affinity, taints, or available resources permit scheduling.
* **CEL has no registry client, live node lookup, or wall clock.** Freshness is computed by the controller, and snapshot expiry is bounded by its included evidence. If the controller stops, its last snapshot and labels can become stale; strict CEL alone cannot enforce a real-time TTL. Readiness checks reconciliation staleness and snapshot expiry. Production operators must monitor it and suspend sandbox scheduling during an outage. Offline evaluation can reject expired snapshots because it has a clock.
* **Admission trust is administrative.** Only CI signing keys and controller-owned parameters are trusted. Signing validates claim consistency and the required execution records but does not independently rerun the workload or authenticate every trace artifact. Protect the controller namespace, signing keys, RuntimeClasses, snapshot CRD, and node-probe credentials. The probe has powerful CRI socket access. The supplied RBAC is a starting point for a trusted infrastructure namespace, not a defense against a compromised privileged probe or cluster administrator. Compatibility policy does not replace Pod Security controls for privileged workloads, host namespaces, or host mounts. Restrict direct Pod binding and scheduler/`pods/binding` permissions; those paths can bypass intended scheduling controls. Reconciliation revokes obsolete SENTRYCHECK-owned health labels. Offline `evaluate` needs `--config` to detect managed runtime names omitted entirely from a supplied snapshot. See [docs/AUDIT-ADMISSION-V03.md](docs/AUDIT-ADMISSION-V03.md).
* **Evidence claims remain scoped.** The PRD's unnamed July 2026 post-mortem, unnamed GitHub issue, blanket eBPF-hard-failure claim, PostgreSQL 16/io_uring example, and novelty claim are not accepted as verified facts. See [docs/PRD-REVIEW.md](docs/PRD-REVIEW.md).
